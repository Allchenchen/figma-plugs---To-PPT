# 开发约束：最小范围修复与稳定基线

后续所有增量修改必须遵守本文。Cursor 规则镜像：`.cursor/rules/minimal-fix-baseline.mdc`。

## 1. 已验收稳定基线

### 1.1 文字（2026-10-26 替换后的基线）

以下行为视为**保护基线**。旧规则（百分比行高写成多倍行距、按视觉行拆成多个文本框、行距统一时交给 PowerPoint 自己折行）已替换，不得再写回。断行的完整条文在 `docs/conversion-rules.md` 的「文字断行」。

| 能力 | 规则 |
|---|---|
| 一个文本节点 | 一个文本框；框用 Figma 测好的尺寸；关闭自动适应 |
| 视觉行 | 从文本 SVG 读取；自动折行写成同一段里的软换行，并关闭自动换行。tspan 行尾自带的换行符只表示本行结束，不另拆空行 |
| 按回车 | 段落号只数回车。U+2028 和自动折行留在同一段，行距写在这一段上。禁止用规范化后的 `\n` 个数当段落号 |
| 行距 | 相邻视觉行的实测距离，写成精确磅值。距离变化时在同一个文本框里另起一段。回车不并进上一段，行高不同的行不用邻居的行高 |
| 字重 | Medium 写成 Medium，Semibold 写成 Semibold。只有 Bold / Black / Heavy 加粗。缺样式时保留样式名并报告 |
| 对齐 | 水平、垂直对齐按 Figma。四边内边距为 0，不用基线当上边距 |
| 段间距离 | 段内行距与按回车后的段距只计一次。减去段距后的行距若小于该行字号，行距改回整段基线差，段距不再另写 |
| 文字颜色 | 每个字符段保留自己的实色。读到实色时不写成黑色 |
| 字距 | 百分比先换成像素再写成磅，只在字符上写一次 |
| 换行保留 | 软换行写进文本，接收方改字后这些换行仍在 |
| 原始换行字符 | 继续读取并传递，不 `trim` 丢空行。字符原文照写 |
| 透明度 | 文字透明度留在字符上，不丢掉，也不烘焙成灰色 |
| 图片字 | 图片填充的标题按原矩形导出图片 |
| 页面范围 | 只导出当前选中的可见顶层 Frame。没选中的不补。隐藏图层不导出 |

相关回归（修改文本链路时必须跑）：

- `test/text-boundaries.test.ts`
- `test/text-wrap.test.ts`
- `test/text-dup-repro.test.ts`
- `test/text-paragraph-rules.test.ts`（换行相关断言）

### 1.2 其他能力

仅当用户**明确验收**后，才可写入本节并视为基线。  
**不得**自行认定「现有实现都已正常」。  
行距视觉、对齐等未验收项可按后续任务处理，但不得重写已正常的换行机制。

## 2. 每次只处理明确提出的问题

修改前简要列出：

1. 本次具体问题  
2. 涉及文件、函数、调用路径  
3. 计划修改的最小范围  
4. 可能影响的已正常功能  

阅读范围可以更宽；**修改范围仅限列表**。

禁止顺带：无关重构/目录调整、无关依赖升级、未要求的功能扩展、全局字号/DPI/行高/框尺寸/坐标规则调整、替换整套文本转换流程。

## 3. 优先最小必要修复

- 在产生问题的具体环节修复；不默认改上游全部数据或下游全部输出。  
- 继续使用 Reader → IR → Converter → OOXML。  
- 复用已正确实现，不按偏好重写。  
- 规则须通用：可按节点属性/结构/能力分支；禁止页面、节点 ID、文案硬编码；禁止用新的全局补偿修局部问题。  
- 「最小范围」= **影响面**最小，不是只追求改动行数最少。

## 4. 公共逻辑变更：影响评估

可在不影响已正常行为的范围内修复时，直接实施。

若必须改动以下公共逻辑，**先书面说明再改**（会改变已验收规则/默认配置/视觉时：**暂停并等待确认**）：

- 文本解析与段落划分  
- 换行生成  
- 字号或单位换算  
- 坐标及尺寸映射  
- 文本布局补偿  
- 公共 OOXML 后处理  

须说明：

1. 为何不能在更小范围解决  
2. 哪些已有功能可能受影响  
3. 如何保证已正常输入的输出不变  
4. 需增加的回归测试  

## 5. 先保护已有结果，再验证新修复

- 修改前记录：代码状态、导出配置、工作区未提交变更（勿覆盖用户已有改动）。  
- 保留已验收样例与测试；**不覆盖**原始夹具；新诊断/导出另存。  
- 换行基线回归至少确认：文字与换行未丢、段落/软换行边界不变、富文本不错位、多行不再并成单行、仍为原生可编辑文本。  
- 新问题修完后运行：针对性测试 + 相关模块回归 + **全部**现有测试 + `typecheck` + `build`。  
- 禁止删测试、放宽断言或擅自改预期掩盖回归。更新预期须说明原因；涉及已验收行为须先确认。

## 6. 出现回归时

1. 停止扩大修改范围  
2. 定位本次引入回归的变更  
3. 优先撤销或收窄本次问题相关改动  
4. 改用影响更小的方案  

禁止为补救而连续改其他正常模块；禁止覆盖用户未提交修改；禁止用整仓库回滚撤销本任务。

## 7. 完成后报告

- 问题与根因  
- 实际修改的文件和函数  
- 哪些转换行为改变了  
- 已正常功能的回归结果  
- 是否修改了默认配置或公共规则  
- 仍需人工验证的视觉项  

结构测试通过 ≠ 视觉完全一致；无真实渲染条件时明确标注「结构验证通过 / 视觉待验证」。

## 最终原则

只修本次明确问题 → 不改无关正常内容 → 不破坏已验收行为 → 公共规则必改则先说明并等待确认 → 增量、通用、可回溯。
